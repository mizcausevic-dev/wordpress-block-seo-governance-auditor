# Why We Built This

Most WordPress SEO audits still evaluate pages at the page level, not the block level. That misses the actual problem on modern editorial sites: good information can still become weak answer-surface material when heading order collapses, FAQ blocks stay too shallow, or promotional layouts push the useful guidance too far down the page.

WordPress Block SEO Governance Auditor exists to make that structure visible. Instead of treating every post like an isolated URL with a score, it asks how the block stack is shaping readability, question-answer extraction, and structured data opportunities.

That matters because answer engines increasingly reward pages that are not just keyword-relevant, but also structurally easy to interpret. When a page mixes inspiration, instructions, and merchandising without clear boundaries, it becomes harder to extract safe, factual answers from it. The copy might be good, but the layout still weakens it.

The design philosophy for this repo is simple:

- operator-first, so weak pages are easy to identify quickly
- WordPress-native, so block anatomy stays central to the audit
- answer-surface aware, so the goal is retrieval-safe structure, not only rank theater
- practical, so every issue points to a concrete editorial or template move

This first version focuses on:
- page-level audit scores
- FAQ and schema opportunity lanes
- verification of overall block posture
- a WordPress plugin starter export for portfolio credibility

The roadmap from here is clear:
- richer block parser inputs from real post content
- template-level auditing for recurring layout debt
- Gutenberg-specific remediation suggestions
- integration with broader AEO and answer-surface release tooling
